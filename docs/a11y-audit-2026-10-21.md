## Reading this honestly

- Qt Controls (buttons, sliders, switches from
  `components/controls/`) expose their own `text` through the
  platform accessibility bridge where the style provides it; the
  gaps that matter are **icon-only custom controls** built on
  `MouseArea`/`CustomMouseArea` with no label fallback.
- First AT-SPI runtime evidence landed 2026-10-21 (below); the
  full screen-reader pass against a live session (tracked in the
  QA repo lanes) is still owed, so surface claims stay scoped to
  what each probe actually observed.
- Keyboard reachability is a separate axis from naming; the focus
  contracts (`tests/test_focus_contract.py`,
  `tests/test_bar_interaction_contract.py`) cover part of it.

## AT-SPI runtime probe — 2026-10-21 (first runtime evidence)

Method: an isolated Quickshell harness (committed as
`tests/atspi/harness.qml`; representative controls: one TextButton,
one IconButton with `accessibleName`, one ToggleRow, one
StyledSlider with `accessibleName`) launched with
`QT_ACCESSIBILITY=1 QT_LINUX_ACCESSIBILITY_ALWAYS_ON=1` on the live
Wayland session, then the AT-SPI tree walked over raw D-Bus with
`tests/atspi/probe.py` (`org.a11y.Bus` → registry root → recursive
`GetChildren`).

Observed accessibles owned by the harness application:

| Role | Name | Source control |
| --- | --- | --- |
| application | quickshell | harness process |
| push button | Apply appearance changes | TextButton visible label |
| push button | Close Welcome | IconButton `accessibleName` |
| check box | Night mode | ToggleRow row label |
| slider | Output volume | StyledSlider `accessibleName` |

This proves the shared-control naming reaches real assistive-tech
consumers with correct roles.

  appeared in the AT-SPI tree**. This is a real gap (focus/window
  activation may gate delegate exposure); it is recorded, not
  explained away.

Still not covered: launcher rows and lock in the tree, and any
screen-reader task-completion pass. The release accessibility
gate stays FAIL until those exist.
