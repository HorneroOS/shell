## Reading this honestly

- Qt Controls (buttons, sliders, switches from
  `components/controls/`) expose their own `text` through the
  platform accessibility bridge where the style provides it; the
  gaps that matter are **icon-only custom controls** built on
  `MouseArea`/`CustomMouseArea` with no label fallback.
- First AT-SPI runtime evidence landed 2026-10-21 (below); the
  full screen-reader pass against a live session (tracked in the
  QA repo lanes) is still owed, so surface claims stay scoped to
  what each probe actually observed.
- Keyboard reachability is a separate axis from naming; the focus
  contracts (`tests/test_focus_contract.py`,
  `tests/test_bar_interaction_contract.py`) cover part of it.

### Launcher retest (same day, resolving the gap above)

The launcher gap was a deployment artifact, not a shell defect.
The second instance in the run above used the default config at
`~/.config/quickshell`, which was a stale checkout at `a8605f8`
(pre-dating the launcher `Accessible` slice): its
`modules/launcher/items/AppItem.qml` contained zero `Accessible`
attached properties, while `main` has them. After a fast-forward
of that checkout to `main` (`944294c`), the identical probe on
the full shell with the launcher open exposed every row as a
named `push button` (Zen Browser, Discord, Thunar File Manager,
Agent Toolkit Desktop, Cursor, GTK Settings, Chromium, Ghostty,
GPU Screen Recorder, guitarix, kitty, OBS Studio), alongside the
bar buttons. A pristine copy of the repo run from another path
showed the same tree, and isolated harnesses bisecting
`StyledListView`, `ScriptModel`, state-assigned delegates and the
real `Wrapper → Content → ContentList → AppList` chain all
exposed their rows, ruling out a composition defect. The probe
depth cap was raised from 10 to 30 so deep real trees cannot be
pruned silently again. Lesson recorded: AT-SPI evidence must name
the exact checkout revision it was taken from.

### Lock content retest (same day)

The lock content (`Center` + `InputField`) was probed with
`tests/atspi/run-lock-probe.sh`, which stages the real lock
module with an inert `Pam` stub (`tests/atspi/lockstub/Pam.qml`)

`text: Password` (the editable password field) and
`push button: Unlock`. Static declarations are pinned by
`tests/test_lock_a11y.py`. This covers the lock *content*; the
real session-lock surface and any screen-reader task-completion
pass are still not covered. The release accessibility gate stays
FAIL until those exist.

## Appearance option delegates — runtime retest (2026-10-23)

The earlier Appearance probe could not instantiate option delegates because
the default theme catalogue was empty and sections remained collapsed. The
new `tests/atspi/run-appearance-probe.sh` stages the real `AppearancePane`
and real option delegates in a scratch Quickshell config. It supplies a
read-only `horneroctl` fixture, temporary HOME/XDG tree, and one generated
wallpaper; no appearance command is applied and no lock surface is engaged.
The runner expands the same sections through the pane's `setAllSections`
method, then checks the AT-SPI roles and labels through the raw D-Bus
`tests/atspi/probe.py` walker, filtered to the launched Quickshell process PID
so another application cannot satisfy the assertions.
The fixture logs every intercepted CLI call, refuses state-changing commands,
and stubs startup scheme-cache regeneration and wallpaper palette preview;
these calls run only against temporary test paths and never reach the real
CLI/backend.

Command:

```sh
tests/atspi/run-appearance-probe.sh
```

Observed on the Wayland development host on 2026-10-23 (automatically
detectable runtime evidence, not an Orca or keyboard task). The scoped probe
walked 129 named accessibles owned by the harness process and all expected
labels were present:

```text
push button: Hornero AT-SPI Palette tonal-spot
push button: Hornero AT-SPI GTK Theme
push button: Hornero AT-SPI Icon Theme
push button: Material font family
push button: Adwaita Sans
push button: Probe Wallpaper
PASS: Appearance option delegates are exposed by AT-SPI
```

The focused static tests also passed:
`python3 -m pytest tests/test_appearance_a11y.py tests/test_appearance_pane_load.py -q`
(5 passed). This verifies runtime exposure for the catalogue-backed theme,
GTK, icon, font, and wallpaper option rows using the shipped delegates. It
does not verify keyboard focus order, actual selection actions, the live lock
surface, or screen-reader task completion. The accessibility gate and #221
remain **FAIL / OPEN** until those separate checks are recorded.
