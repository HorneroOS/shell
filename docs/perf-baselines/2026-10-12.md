# Hornero Shell steady-state reference — 2026-10-12

This is one observed sample set, captured on 2026-10-12 UTC while the shell was
already running. It provides a concrete review reference for future comparable
runs; it is not a performance guarantee, target, or claim about other systems.

## Context

- Shell revision: `2df8b5e` (`main` at capture time).
- Quickshell: `0.3.1`, Arch Linux distribution build.
- Compositor: Hyprland.
- Active monitors: 1.
- Session age: approximately 7 hours 17 minutes.
- Mode: steady-state sampling; the desktop was not restarted.
- Samples: 5, 2 seconds apart.
- The measuring command ran in a user systemd unit capped at 128 MiB memory,
  zero swap, and 100% of one CPU. The existing shell was outside that unit;
  this limit constrained the measurement harness, not the shell being measured.

Host identity, process IDs, total host memory, CPU topology, user name, and
full timestamps are omitted. `qml_files_available` is also omitted because it
counts files present in the config tree, not files loaded by the running shell.

## Reproduction

From a running Hornero Shell session, run:

```sh
systemd-run --user --wait --pipe --working-directory="$PWD" \
  -p MemoryMax=128M -p MemorySwapMax=0 -p CPUQuota=100% -- \
  ./scripts/perf-baseline.sh --samples 5 --interval 2 --format json
```

Do not add an unrestricted raw JSON report to the repository. Review and
sanitize any proposed follow-up capture using the policy in
[`../PERF_BASELINE.md`](../PERF_BASELINE.md).

## Limits of this capture

- It is not a clean-session or cold-start measurement.
- It does not measure greeter-to-desktop time, first rendered frame, or
  per-surface frame cost.
- One five-sample run cannot establish a regression or improvement; compare
  repeated runs under similar session age, open-window, and compositor
  conditions.
- The IPC metric is one `lock isLocked` round trip, not general shell
  responsiveness.
