# Hornero Shell steady-state observation — 2026-10-14

This is a sanitized three-sample capture from a running development desktop.
It records one point in time for future investigation; it is not a performance
guarantee, target, or claim about other systems.

## Context

- Installed Shell: `hornero-shell 1.2.14-1`; its source revision was not established.
- Quickshell: `0.3.2`, Arch Linux distribution build.
- Compositor: Hyprland `0.56.2`.
- Active monitors: 1.
- Session age: approximately 3 hours 34 minutes.
- Mode: steady-state sampling; the desktop was not restarted.
- Samples: 3, 1 second apart.
- The measurement harness ran in a user systemd scope capped at 2 GiB memory
  and zero swap. The already-running Shell was outside that scope; the cap
  applied only to the measurement process.

Host identity, process IDs, user name, total host memory, CPU topology, and
full timestamp are omitted. `qml_files_available` is omitted because it counts
files in the selected config tree, not QML files loaded in memory.

## Reproduction

From a running Hornero Shell session, run:

```sh
systemd-run --user --wait --pipe --working-directory="$PWD" \
  -p MemoryMax=2G -p MemorySwapMax=0 -- \
  ./scripts/perf-baseline.sh --samples 3 --interval 1 --format json
```

The raw JSON report is intentionally not committed because it includes
machine and session details. The run did not use `--restart` and completed
successfully.

## Limits of this capture

- This is not a clean-session or cold-start measurement. Open-window and
  drawer state were not controlled or recorded.
- The installed Shell package predates the current repository release and its
  exact source revision is unknown. Do not treat this as a measurement of
  current `main`.
- It is not directly comparable to the October 12 or 13 captures: package
  revision, session age, sample count/interval, and UI state differ.
- The measurements do not establish a regression, memory leak, or improvement.
  They only show readings across this short sampling window.
- The capture does not measure greeter-to-desktop time, first rendered frame,
  or per-surface frame cost. IPC is one `lock isLocked` round trip, not general
  shell responsiveness.
