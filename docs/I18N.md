# Shell UI languages (i18n)

The shell speaks English (the source language) and Argentine Spanish
(`es_AR`). Every user-visible string goes through `qsTr()`; the
translations live in reviewable Qt Linguist catalogs under `i18n/`.

## For users

Control Center, **System**, **Language** has three choices:

| Choice | What it does |
| --- | --- |
| Automatic (default) | Follows the system UI language (`LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, `LANG`). The label shows what it resolves to. |
| English | Always English. |
| Español (Argentina) | Always Argentine Spanish. |

The choice is stored as `general.language` in `shell.json`
(`"auto"`, `"en"` or `"es_AR"`).

What changes when, stated plainly:

- **Live:** every label, button, page title, description and tooltip
  whose text comes from a `qsTr()` binding switches as soon as you pick a
  language. No restart needed.
- **Next time it is shown:** text that was handed over once, such as a
  toast or notification already on screen, keeps its wording until it is
  shown again.
- **After a shell restart:** everything, including the standalone lock
  process (`lock.qml`) when that opt-in is enabled.
- **Not changed:** dates, times and numbers keep following your system
  region (`LC_TIME`, `LC_NUMERIC`). Pick the region in your system locale
  settings if you want Spanish weekday names.
- Automatic with any Spanish system locale (`es_ES`, `es_MX`, ...) uses
  the Argentine catalog, the closest one shipped. Other languages fall
  back to English.
- If the catalog cannot be read, the shell stays in English and the
  Language panel says why.

Javi's assistant copy (`services/assistantcopy.js`) and spoken lines
(`modules/companion/javivoice.js`) keep their own English/Spanish
tables, which tests run under node; they follow the same setting through
`Language.uiLocale` (Javi's own Voice language setting still wins when it
is not "auto").

Not translated by this catalog: the layout-preset names and descriptions
(they come from `presets/*.json`), plugin text (plugins ship their own
catalogs, see `docs/PLUGINS.md`), the restart cover (`reloadcover/`), and
text that comes from other programs (app names, `horneroctl` output,
device and network names).

## How it works

- `plugin/src/Hornero/translator.{hpp,cpp}`: `Translator` (QML
  singleton in `Hornero`) parses `i18n/hornero_<locale>.ts` directly,
  installs it as a `QTranslator` and calls `QQmlEngine::retranslate()`,
  which re-runs every binding that calls `qsTr()`. Quickshell 0.3.2 has
  no translation loader of its own and uses a plain `QQmlEngine`, so
  `Qt.uiLanguage` alone would not load anything; this C++ piece is the
  minimum QML cannot do. Only finished translations are used
  (`unfinished`, `vanished` and `obsolete` fall back to English). A
  lookup tries the file's own context first and then the source text in
  any context, so `qsTr(variable)` finds a string marked elsewhere.
- Reading the `.ts` source (not a compiled `.qm`) keeps a source checkout
  and the package identical: there is no build step that can go stale.
- `services/Language.qml` resolves `general.language` and loads the
  catalog; `shell.qml` and `lock.qml` instantiate it at startup.
- Plurals use `qsTr("%n thing(s)", "", count)`; the catalog holds both
  Spanish forms.

## For developers

1. Wrap every user-visible literal in `qsTr()`. Whole sentences, with
   `%1`-style placeholders; never concatenate translated pieces.
2. Strings built in plain JS that tests run under node (for example
   `modules/controlcenter/taskbar/barorder.js`) are marked with
   `QT_TR_NOOP()` in the QML file that displays them and shown with
   `qsTr(value)` there.
3. Run `scripts/i18n_update.sh` (needs the Qt 6 `lupdate`, package
   `qt6-tools` on Arch, `qt6-l10n-tools` on Debian/Ubuntu). New strings
   appear as `type="unfinished"`.
4. Translate them in `i18n/hornero_es_AR.ts` (Qt Linguist, or by hand:
   fill the `<translation>` and drop `type="unfinished"`).
5. `python3 -m pytest tests/test_i18n_catalog.py -q` must pass.

The gate (`tests/test_i18n_catalog.py`, CI job `i18n`):

- every literal `qsTr()` / `QT_TR_NOOP()` in the runtime tree is in the
  catalog (catches a forgotten `lupdate`);
- every catalog message has a finished Spanish translation, unless it is
  listed in `i18n/es_AR.untranslated` (the baseline; it is empty today
  and may only shrink: a listed string that is now translated fails too);
- placeholders (`%1`, `%n`, `%L1`), HTML tags and leading/trailing
  whitespace match the English;
- product names stay as written and no Spain-Spanish tuteo slips in;
- in CI, `scripts/i18n_update.sh --check` regenerates the catalog with
  `lupdate` and fails if it is stale.

## Argentine Spanish style guide

The Hornero voice in Spanish is the same as in English: short, warm,
plain, never cute at the expense of clarity, never blaming the user.

- **Voseo, always.** Instructions to the person use vos: *Elegí*,
  *Abrí*, *Probá*, *Tocá*, *Escribí*, *Conectá*, *Volvé*; *podés*,
  *tenés*, *querés*, *sos*. Never *tú* forms (*elige*, *abre*, *puedes*,
  *tienes*) and never *vosotros*.
- **Buttons, menu items, toggles and setting names** use the infinitive
  or a noun, like most Argentine software: *Guardar*, *Restablecer*,
  *Abrir*, *Mostrar reloj*, *Tamaño del texto*. Sentences that talk to
  the person (hints, empty states, confirmations) use voseo.
- **Natural, not literal.** Rewrite the sentence the way someone in
  Buenos Aires or Córdoba would say it on a calm day. Keep it about as
  short as the English; Spanish runs longer, so trim filler.
- **Sentence case**, like the English. No exclamation marks unless the
  English has one. Keep `…` where the English has it.
- **Placeholders and markup** (`%1`, `%n`, `<b>`, `\n`) stay, in the
  order Spanish needs.
- **Units and symbols** stay: `%`, `GiB`, `Hz`, `°C`, `px`, `ms`.

### Names that stay as written

Product, feature and proper names are not translated: HorneroOS,
Hornero, Hornero Signal, Signal, Cockpit, Cockpit Clear, Chromatic,
Clear Ink, PluginKit, Javi (the companion), Hermes (the assistant), and
the experience mode names (Focus, Everyday, Signal, Gaming, Studio, as
in the Spanish handbook). Layout preset names (Minimal Top, Floating
Island, ...) stay too. Third-party names stay: Hyprland, Niri,
PipeWire, GTK, Qt, QML, Bluetooth, Wi-Fi, VPN, WireGuard, NetBird,
Steam, Gamescope, MangoHud, CPU, GPU, RAM.
