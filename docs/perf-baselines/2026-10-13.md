# Hornero Shell steady-state observation — 2026-10-13

This is a sanitized five-sample capture from a running HorneroOS desktop. It
records one point in time for future comparison; it is not a performance
guarantee, target, or claim about other systems.

## Context

- Shell revision: `68145aa` (`main` at capture time).
- Installed Hornero Shell: `1.2.13-1`.
- Quickshell: `0.3.2`, Arch Linux distribution build.
- Compositor: Hyprland.
- Active monitors: 1.
- Session age: approximately 1 hour 21 minutes.
- Mode: steady-state sampling; the desktop was not restarted.
- Samples: 5, 2 seconds apart.
- The measurement harness ran in a user systemd unit capped at 128 MiB memory,
  zero swap, and 100% of one CPU. The already-running Shell was outside that
  unit; the cap applied to the measurement process, not the Shell being
  measured.

Host identity, process IDs, user name, total host memory, CPU topology, and
full timestamp are omitted. `qml_files_available` is omitted because it counts
files in the selected config tree, not QML files loaded in memory.

## Reproduction

From a running Hornero Shell session, run:

```sh
systemd-run --user --wait --pipe --working-directory="$PWD" \
  -p MemoryMax=128M -p MemorySwapMax=0 -p CPUQuota=100% -- \
  ./scripts/perf-baseline.sh --samples 5 --interval 2 --format json
```

The raw JSON report is intentionally not committed because it includes
machine and session details.

## Limits of this capture

- It is not a clean-session or cold-start measurement.
- It does not measure greeter-to-desktop time, first rendered frame, or
  per-surface frame cost.
- It is not directly comparable to the 2026-10-12 captures: Shell and
  Quickshell versions and session ages differ. The higher memory values are a
  signal to investigate with controlled repeated measurements, not proof of a
  regression or its cause.
- The IPC metric is one `lock isLocked` round trip, not general shell
  responsiveness.
