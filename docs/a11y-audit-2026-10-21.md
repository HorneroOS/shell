## Reading this honestly

- Qt Controls (buttons, sliders, switches from
  `components/controls/`) expose their own `text` through the
  platform accessibility bridge where the style provides it; the
  gaps that matter are **icon-only custom controls** built on
  `MouseArea`/`CustomMouseArea` with no label fallback.
- The shell has no AT-SPI runtime verification yet. Until a screen
  reader pass runs against a live session (tracked in the QA repo
  lanes), every "named" claim here is static evidence only.
- Keyboard reachability is a separate axis from naming; the focus
  contracts (`tests/test_focus_contract.py`,
  `tests/test_bar_interaction_contract.py`) cover part of it.

## Suggested order for #221 slices

1. Lock screen controls (safety-critical, small surface).
2. Launcher rows and dashboard cards (high-traffic custom items).
3. Control Center panes at zero (mechanical, pane by pane).
4. AT-SPI runtime pass in the QA harness; only then revisit the
   release-readiness accessibility gate.
